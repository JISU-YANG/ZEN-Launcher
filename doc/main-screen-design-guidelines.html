Extension Area Guideline

확장영역은 별도 화면이 아니라
런처의 흐름을 이어주는 레이어여야 한다.

확장영역은 사용자가 "기능을 열기 위해 이동하는 곳"이 아니라, 런처를 사용하는 도중 필요한 순간에만 자연스럽게 펼쳐지는 공간으로 정의한다. 항상 존재감을 드러내기보다, 메인 런처의 맥락을 유지한 채 필요한 정보와 액션을 짧고 정확하게 보강해야 한다.

핵심 방향

  • 확장영역은 메인을 대체하지 않고 메인 옆에서 맥락을 보충한다.
  • 호출은 명확해야 하지만 등장 자체는 과장되지 않아야 한다.
  • 사용 빈도가 높아질수록 조작 비용이 줄어드는 구조여야 한다.
  • 정보 밀도는 높일 수 있지만 시선 중심은 계속 런처 메인에 남아 있어야 한다.

개념 스케치

1. 역할 정의

확장영역은 메인 런처의 정보 구조를 깨지 않고, 한 단계 더 깊은 정보나 즉시 실행 도구를 담는 공간이다. 따라서 독립된 페이지 문법보다 "붙었다가 사라지는 도구층"의 문법을 따라야 한다.

메인과의 관계

메인 화면은 탐색과 선택의 중심이다. 확장영역은 세부 확인, 빠른 실행, 짧은 설정 변경처럼 메인의 다음 한 걸음을 지원하는 역할에 집중한다.

등장 방식

사용자가 의도한 트리거에 의해 나타나야 한다. hover만으로 예기치 않게 열리기보다 클릭, 포커스 유지, 명확한 단축 동작처럼 신뢰 가능한 신호에 반응하는 편이 좋다.

퇴장 방식

기능을 마치면 쉽게 닫히고, 다시 돌아왔을 때 문맥이 이어져야 한다. 닫힘은 가볍고 빠르게, 복귀는 예측 가능하게 설계한다.

2. 호출 원칙

"필요할 때 나오는 구조"를 만들기 위해서는 호출 조건이 가장 중요하다. 항상 열려 있으면 잡음이 되고, 너무 깊게 숨으면 활용 빈도가 떨어진다.

01

사용자 의도 감지

토글 버튼, 특정 아이콘 선택, 검색 결과의 세부 액션, 단축키 등 명시적인 신호를 우선한다.

02

적절한 크기 선택

보여줄 정보와 필요한 조작 수에 따라 S, M, L 중 하나를 고른다. 먼저 작은 크기로 해결 가능한지 검토하고, 정말 필요할 때만 확장한다.

03

맥락 유지

열린 뒤에도 메인 런처의 현재 선택과 위치를 잃지 않게 한다. 확장영역 제목, 대상 아이템, 이전 액션이 바로 읽혀야 한다.

04

짧은 종료 또는 단계적 확대

S에서 해결되지 않으면 M, M에서 해결되지 않으면 L로 커질 수 있어야 한다. 반대로 작업이 단순해지면 다시 줄어드는 흐름도 가능해야 한다.

3. 크기 체계

확장영역의 기준 단위는 런처 메인 영역의 가시 크기다. M을 기준 크기로 두고, S는 0.2x, L은 2x로 정의한다. 비율은 절대 픽셀보다 관계 유지가 중요하다.

S = 메인 0.2배

짧은 확인과 한 번의 액션

  • 한눈에 끝나는 상태 확인, 토글, 단일 CTA에 적합하다.
  • 예: 날씨 요약, 예약 상태, 빠른 토글, 최근 실행 추천 1~2개.
  • 메인을 가리지 않고 옆이나 위에 가볍게 붙는 형태가 좋다.
  • 닫기 없이도 외부 클릭, 포커스 이동으로 자연스럽게 사라질 수 있다.
M = 메인 1배

기본 확장 단위

  • 확장영역 설계의 기준 크기다.
  • 정보 확인과 2~3단계 조작을 함께 처리할 때 적합하다.
  • 예: 퀵툴 그리드, 상세 날씨, 실행 옵션 선택, 간단한 설정 편집.
  • 메인과 동등한 존재감을 가지되, 시각적 강조는 한 단계 낮게 유지한다.
L = 메인 2배

집중이 필요한 작업

  • 목록 탐색, 다중 설정, 미리보기, 긴 설명처럼 공간이 필요한 경우에만 사용한다.
  • 예: 프로그램 편집, 고급 옵션, 다수의 후보 비교, 복합 도구 패널.
  • 메인과 연결된 확장으로 보이되 사실상 작업 캔버스 역할을 한다.
  • 항상 L로 시작하지 말고, M에서 진입 후 확대되는 흐름을 우선 고려한다.
크기 적합한 콘텐츠 권장 인터랙션 피해야 할 것
S 상태 요약, 토글, 즉시 실행 1클릭 완료, 빠른 닫힘, 가벼운 애니메이션 스크롤, 복수 단계 폼, 긴 설명
M 상세 정보, 짧은 설정, 카드형 도구 탭 전환, 2단 구조, 짧은 리스트 과도한 서브 네비게이션, 무거운 모달 문법
L 편집, 탐색, 비교, 다중 액션 검색, 필터, 다단 구성, 명시적 닫기 메인과 완전히 단절된 새 앱처럼 보이는 구성

4. 시각 원칙

확장영역은 메인과 같은 제품 안에 속해 보이되, 정보 밀도와 계층이 명확히 읽혀야 한다. 따라서 배경, 테두리, 움직임은 메인보다 한 단계 더 차분하게 잡는 편이 좋다.

시각 신호

연결감 확장성 주의 오류

  • 메인과 동일한 모서리 체계를 사용하되, 그림자와 배경 대비로 확장 레이어를 구분한다.
  • 등장 애니메이션은 슬라이드보다 부드러운 확장 또는 페이드 업이 자연스럽다.
  • 색상 강조는 CTA보다 정보 상태와 구조 구분에 우선 사용한다.
  • 헤더는 짧고 명확하게, 본문은 바로 행동할 수 있는 밀도로 유지한다.

레이아웃 신호

  • S는 단일 행 또는 단일 카드 중심으로 구성한다.
  • M은 헤더 + 본문, 또는 요약 + 상세의 2단 문법이 안정적이다.
  • L은 좌우 분할 또는 상단 필터 + 하단 내용 구조가 적합하다.
  • 어떤 크기에서도 첫 화면에서 핵심 액션이 보여야 한다.
확장영역이 자주 사용되길 원한다면, 매번 "열고 읽고 해석"하게 만들면 안 된다. 첫 시선에서 무엇을 할 수 있는지 바로 이해되는 밀도가 중요하다.

5. 상태 전이 가이드

확장영역은 정적인 박스보다 상태를 가진 유기적인 레이어로 보는 편이 맞다. 특히 S, M, L 사이를 오갈 수 있어야 자연스러운 사용 흐름이 만들어진다.

권장 흐름

  1. 기본은 닫힘 상태에서 시작한다.
  2. 짧은 확인은 S로 연다.
  3. 추가 정보가 필요하면 같은 컨텍스트를 유지한 채 M으로 확장한다.
  4. 편집이나 탐색이 길어지면 L로 전환한다.
  5. 작업 완료 후에는 M 또는 닫힘으로 자연스럽게 복귀한다.

전이 규칙

  • 크기 전환은 내용 교체보다 레이어 성장처럼 느껴져야 한다.
  • 전환 시 헤더 제목과 대상 정보는 유지해 사용자가 맥락을 잃지 않게 한다.
  • 닫힘 후 다시 열었을 때 최근 상태를 부분 복원하면 반복 사용성이 좋아진다.
  • 단, 오류나 민감한 설정 화면은 매번 초기 상태로 시작하는 것이 더 안전할 수 있다.

6. 화면 예시

아래 예시는 실제 UI 시안이라기보다 확장영역이 어떤 톤과 밀도로 보여야 하는지를 설명하기 위한 구조 예시다.

S 예시

예: "현재 날씨", "예약 종료까지 12분", "최근 항목 실행"처럼 한 번의 판단으로 끝나는 정보.

M 예시

예: 날씨 상세, 빠른 도구 모음, 아이템 실행 옵션, 메인 흐름을 보조하는 기본 확장 화면.

L 예시

예: 프로그램 편집, 다중 항목 탐색, 검색과 설정이 함께 필요한 고도화 패널.

7. Do / Don't

Do

  • 메인 런처의 현재 선택과 문맥을 확장영역 안에서도 이어준다.
  • 항상 작은 크기에서 해결 가능한지 먼저 검토한다.
  • 확장영역의 첫 화면에서 핵심 정보와 액션을 바로 노출한다.
  • 크기 전환 시 제목, 대상, 위치를 유지해 사용자가 길을 잃지 않게 한다.
  • 반복 사용 기능일수록 열림과 닫힘의 비용을 최소화한다.

Don't

  • 확장영역을 항상 열려 있는 사이드바처럼 고정하지 않는다.
  • 메인보다 더 강한 색과 장식으로 시선을 빼앗지 않는다.
  • S 크기에 스크롤과 다단계 폼을 밀어 넣지 않는다.
  • L 크기를 기본값처럼 사용하지 않는다.
  • 닫았다 다시 열 때 완전히 다른 위치와 레이아웃으로 보여주지 않는다.

8. 구현용 문장 정리

아래 문장은 실제 설계나 개발 태스크를 나눌 때 바로 기준 문장으로 옮겨 적을 수 있도록 정리한 버전이다. 

확장영역 설계 원칙

1. 확장영역은 메인 런처의 보조 레이어이며 독립 화면처럼 동작하지 않는다.
2. 열림 조건은 사용자 의도가 명확한 트리거를 우선한다.
3. 기본 크기는 M(메인 1배)이며, S(0.2배)와 L(2배)는 목적에 따라 단계적으로 전이한다.
4. S는 단일 상태 확인 또는 1회 액션, M은 기본 확장, L은 편집/탐색/다중 액션에 사용한다.
5. 메인과의 연결감은 유지하되 시각적 강조는 메인보다 한 단계 낮게 유지한다.
6. 크기 전환은 화면 교체가 아니라 같은 레이어의 성장처럼 느껴져야 한다.
7. 반복 사용 시 재진입 비용이 낮아야 하며, 닫힘과 복귀는 예측 가능해야 한다.
