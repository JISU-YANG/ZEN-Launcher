Extension Area Guideline

현재 확장영역의 기준 형태는
하단에서 올라오는 M 사이즈 확장 캔버스다.

지금 구현된 확장영역은 우측 패널이나 롤아웃 장치가 아니라, 메인 런처 아래쪽 경계가 열리면서 위젯과 도구를 담는 중간 크기의 작업면이 펼쳐지는 구조에 가깝다. 따라서 가이드도 "우측에서 말려 나온다"가 아니라 "메인 아래에 붙어 있는 M 레이어가 열리고 닫힌다"는 기준으로 설명하는 편이 맞다.

현재 구조 해석

  • 확장영역은 메인 아래에 붙는 하단 확장 캔버스다.
  • 기본 감각은 side panel이 아니라 bottom sheet에 더 가깝다.
  • 지금 보이는 확장영역은 이미 M 크기의 기본형이다.
  • S와 L은 이 M을 기준으로 축소 또는 확장된 변형으로 설명해야 한다.

이 문서의 기준

  • M을 현재 실제 구현 상태로 본다.
  • 메인과 확장영역은 상하 관계로 연결되어야 한다.
  • 핵심 인상은 "하단 덮개가 열리며 작업면이 올라온다"이다.
  • 설명은 현재 구조와 맞지 않는 우측 seam, rail, handle 비유를 쓰지 않는다.

1. 메인 비주얼

현재 확장영역은 메인 런처 아래쪽 경계가 열리면서 M 크기의 확장 작업면이 올라오는 구조로 이해하는 것이 정확하다. 아래 시안은 메인 창 아래에 붙은 얇은 커버와, 그 아래에서 올라오는 S/M/L 레이어의 관계를 보여준다.

SHEET Lworkspace
SHEET Mdefault
SHEET Speek

핵심은 세 크기가 모두 메인 아래에서 열리는 같은 계열의 레이어라는 점이다. 지금 구현 기준에서 M은 "주 확장 작업면"이고, S는 얕게 열린 상태, L은 더 깊게 확장된 상태로 보는 편이 자연스럽다.

2. 현재 구현 기준 해석

문서 표현은 실제 구현과 맞아야 한다. 현재 코드 기준으로 확장영역은 메인 아래에 고정되어 열리고, 내부에 위젯이 임베드되는 구조다.

맞는 표현

  • 하단 확장 레이어
  • 메인 아래에 붙는 M 캔버스
  • 열리고 닫히는 작업면
  • 위젯이 내장되는 확장 영역

맞지 않는 표현

  • 우측에서 말려 나오는 패널
  • 레일과 손잡이 기반 구조
  • 옆으로 꺼내는 도구층
  • 메인과 분리된 플로팅 시트

3. 크기 체계

지금 보이는 확장영역을 M으로 두고, S와 L은 같은 하단 레이어가 덜 열리거나 더 확장된 상태로 설명하는 편이 정확하다.

S = 메인 0.2배

Peek Layer

하단 경계가 살짝 열려 상태 확인이나 한 번의 액션만 빠르게 처리하는 얕은 상태다.

  • 높이가 낮다.
  • 스크롤보다 즉시 실행에 적합하다.
  • 외부 클릭으로 자연스럽게 닫혀도 된다.
M = 메인 1배

Default Layer

현재 구현된 확장영역의 기본형이다. 위젯, 퀵툴, 간단한 설정 편집은 이 단계에서 해결하는 것이 맞다.

  • 헤더, 요약, 액션, 본문이 함께 들어간다.
  • 현재 런처에서 가장 자주 쓰이는 확장 형태다.
  • 문서의 기본 기준점이 된다.
L = 메인 2배

Workspace Layer

M보다 더 깊게 열려 편집, 탐색, 비교처럼 집중이 필요한 작업을 담는 확장 상태다.

  • 목록과 편집 폼을 함께 배치할 수 있다.
  • M에서 추가로 확장되는 흐름이 자연스럽다.
  • 새 화면처럼 느껴질 정도로 분리되면 안 된다.
단계의미적합한 콘텐츠전환 인상
S하단이 살짝 열린 상태상태 요약, 토글, 1회 액션짧게 올라왔다가 빠르게 닫힘
M기본 확장 상태상세 정보, 위젯, 퀵 액션, 짧은 설정메인 아래 작업면이 열림
L집중 작업 상태편집, 탐색, 비교, 다중 액션같은 하단 레이어가 더 깊게 확장됨

4. 호출과 복귀

현재 구조에서는 확장영역이 아래에서 열린다는 점이 전환의 핵심이다. 따라서 등장과 복귀 역시 수직 방향성을 유지해야 한다.

01

명확한 트리거

아이콘, 토글, 퀵 기능 선택처럼 사용자의 의도가 분명할 때만 확장영역이 열린다.

02

M을 기본으로 사용

현재 구현의 중심은 M이다. 대부분의 확장 작업은 M에서 해결하고, 더 단순하면 S로, 더 복잡하면 L로 변형한다.

03

상하 문맥 유지

메인 위, 확장영역 아래의 관계가 계속 읽혀야 한다. 확장영역이 열려도 메인을 대체한 새 화면처럼 보이면 안 된다.

04

아래로 닫히는 복귀

복귀는 사라지는 느낌보다, 아래 작업면이 다시 접히며 내려가는 인상을 주는 편이 현재 구조에 더 맞다.

5. 실제 디자인 제안

M 확장영역은 큰 빈 박스가 아니라, 메인 아래에 붙은 밀도 높은 작업면이어야 한다. 즉 내부는 풍부하되, 바깥 윤곽은 하나의 하단 캔버스로 유지하는 편이 좋다.

헤더 구조

헤더는 제목, 짧은 설명, 상태 뱃지 정도만 두고, 메인 위젯 내용이 바로 이어지게 한다.

퀵 액션 구조

가장 자주 쓰는 액션 1개만 강하게 두고, 나머지는 보조 버튼으로 정리한다. 하단 작업면일수록 액션 흐름이 짧아야 한다.

리스트 / 후보군

L로 확장될 때는 목록과 상세를 함께 다루게 된다. 각 행은 얇고 빠르게 읽히게 구성하는 편이 좋다.

요약 카드

정보 카드는 장식보다 읽힘이 우선이다. 큰 수치, 현재 상태, 추천 액션 순으로 읽히게 정리한다.

지금 구조에서는 "하단 확장 작업면"이라는 기본 인상을 먼저 지키고, 그 안에서 정보 밀도와 도구 밀도를 올리는 편이 더 자연스럽다.

6. Do / Don't

Do

  • 현재 확장영역을 하단에서 열리는 M 캔버스로 정의한다.
  • S와 L을 M의 축소/확장 변형으로 설명한다.
  • 등장과 복귀는 수직 방향성을 유지한다.
  • 메인 위, 확장영역 아래의 상하 관계를 유지한다.

Don't

  • 지금 구조를 우측 롤아웃 패널처럼 설명하지 않는다.
  • 레일, 손잡이 같은 현재 구현과 무관한 비유를 쓰지 않는다.
  • M을 지나가는 중간 상태처럼 설명하지 않는다.
  • 확장영역을 메인과 분리된 새 화면처럼 설계하지 않는다.

7. 구현용 문장 정리

아래 문장은 실제 설계와 개발 태스크에 바로 옮겨 적을 수 있도록 정리한 기준 문장이다.

확장영역 설계 원칙

1. 현재 확장영역의 기본 형태는 메인 런처 아래에서 열리는 M 사이즈 확장 캔버스다.
2. 확장영역은 우측 패널이 아니라 하단 확장 레이어로 설명한다.
3. S(0.2x), M(1x), L(2x)은 같은 하단 레이어의 축소/기본/확장 상태다.
4. M은 현재 구현의 기준형이며, 위젯과 도구는 이 상태를 중심으로 배치한다.
5. 등장 모션은 아래에서 위로 열리는 방향성을 유지한다.
6. 복귀 모션은 작업면이 다시 아래로 접히며 닫히는 인상을 주어야 한다.
7. 확장영역이 열려도 메인과의 상하 관계는 계속 읽혀야 한다.
